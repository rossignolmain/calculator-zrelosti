## Модель

21 фиксированное направление. Для каждого 8 критериев. Ключ ответа на сайте: `directionId:j`, оба индекса от 1. Значение ответа `a` — число. Неотвеченное поле отсутствует в словаре; при расчёте равно нулю, при подсчёте заполненности не учитывается. Явный ответ 0 учитывается как заполненный.

|---|---|---|---|
| 1 | Документирование | 0.15 | 0, 0.5, 1 |
| 2 | Выполнение | 0.2 | 0, 0.5, 1 |
| 3 | Инструменты | 0.1 | 0, 0.5, 1 |
| 4 | Квалификация | 0.1 | 0, 0.5, 1 |
| 5 | Контроль | 0.15 | 0, 0.5, 1 |
| 6 | Обучение | 0.1 | 0, 0.3, 0.5, 1 |
| 7 | Внешний аудит | 0.1 | 0, 0.5, 1 |

## Расчёт направления

`D[j] = w[j] * (answer[j] ?? 0)`

`P = sum(D[1..8])` без промежуточного округления.

Пройти правила от уровня 4 к уровню 1. Первое правило, для которого пройдены порог P и все обязательные минимумы, определяет текущий целочисленный уровень. Если ни одно правило не пройдено, уровень равен 0.

| Уровень | P не ниже | Обязательные значения D |
|---|---|---|
| 1 | 0.225 | D1≥0.075; D2≥0.1; D3≥0.05 |
| 2 | 0.35 | D1≥0.075; D2≥0.1; D3≥0.05; D4≥0.05; D5≥0.075 |
| 3 | 0.65 | D1=0.15; D2=0.2; D3≥0.05; D4≥0.05; D5=0.15; D6≥0.05 |
| 4 | 0.9 | D1=0.15; D2=0.2; D3≥0.05; D4≥0.05; D5=0.15; D6=0.1; D7=0.1; D8=0.1 |

Числовой допуск EPS=1e-9. Равенство: `abs(actual-required) < EPS`. Минимум: `actual >= required-EPS`. Порог P тоже проверяется с этим допуском.

Важные случаи: высокая сумма без обязательного критерия не гарантирует даже уровень 1. Например, при D1=0 остальные максимальные ответы дадут P=0.85 и уровень 0. Промежуток 0.2≤P<0.225 явно не покрыт таблицей 3; сайт возвращает 0. При D6=0.03 (ответ 0.3) уровень 3 недостижим. Регулярный внешний аудит (ответ 1) обязателен для уровня 4.

## Итог

N — число включённых направлений. Исключённое направление не входит в среднее, заполненность и график. Его сохранённые ответы и цель не удаляются. В расчётном объекте исключённое направление имеет P=0, attained=0.

Если N=0: `blocked=true`, внутренний `uzi=0`, на экране значение `—`, результат/экспорт заблокирован, сообщение о необходимости вернуть хотя бы одно направление.

Если N>0: `uzi = Math.round((sum(attained)/N + Number.EPSILON)*100)/100`. Используется JS Math.round, для неотрицательных чисел соответствует округлению половин вверх (C# MidpointRounding.AwayFromZero). Сначала округление, затем определяется шкала.

Шкала с EPS: значение принадлежит строке, если `uzi>=min-EPS` и `(max==null || uzi<max-EPS)`.

- [0,1): Нулевой (отсутствует), красный.
- [1,2): Начальный, оранжевый.
- [2,3): Системный, жёлтый.
- [3,4): Контролируемый, зелёный.
- [4,+∞): Верифицируемый, голубой (по формальному первоисточнику Узи=4, фактический максимум 4).

Полные характеристики в `spec.json`.

`answeredCount = количество присутствующих ответов только во включённых направлениях`.
`totalQuestions = 8*N`.
`progress = answeredCount/totalQuestions*100`, экранный процент до целого через `toFixed(0)`.
`achieved = attained >= target`, `gap = target-attained` если цель не достигнута.

Отображение Uzi: 2 знака после запятой с десятичной запятой. Отображение P: округление до 3 знаков по `Math.round((P+Number.EPSILON)*1000)/1000`, затем `toFixed(3)`, десятичная запятая.

## Цели и категории

По умолчанию все направления включены, ответы отсутствуют, цели всех направлений 1, выбранная категория отсутствует.

- `target1`: ГИС К3, иные ИС госорганов, ИСПДн УЗ-3/4, ЗОКИИ 3 категории, цель минимум 1.
- `target2`: ГИС К2, ИСПДн УЗ-2, ЗОКИИ 2 категории, цель минимум 2.
- `target3`: ГИС К1, ИСПДн УЗ-1, ЗОКИИ 1 категории, цель минимум 3.
- `unknown`: Не знаю класс системы, цель минимум 1.

Выбор категории заново устанавливает цели ВСЕХ направлений ровно в значение категории, в том числе исключённых, и стирает индивидуальные повышения. Выбор категории не изменяет ответы и применимость.

Индивидуальная цель: `min(4,max(categoryMinimum,requestedTarget))`. Кнопки ниже минимума категории отключены. При отсутствии категории минимум равен 1.

## Рекомендации

Для исключённого направления или достигнутой цели список пуст.

Для недостигнутой цели берётся правило именно целевого уровня. Перебираются его minima по возрастанию j. Для каждого нарушенного минимума:

1. Вычислить требуемый ответ `minimum.v / weight[j]`.
2. Найти первый вариант ответа с `option.a >= requiredAnswer-EPS`.
3. Вывести `requirementTitle = criterion.title`, `action = option.label`; запасная action: `Выполнить вид требования полностью`.

Если сформирована хотя бы одна такая рекомендация, больше ничего не добавлять.

Если все минимумы пройдены, но `P<targetRule.pMin-EPS`, выводится ровно одна рекомендация:

- Заголовок `Итоговое значение Pi ниже порога {pMin}`, десятичная запятая.
- Действие `Усильте виды требований: {список}`.
- Список: первые три критерия в исходном порядке, у которых ответ <1, через запятую. Если таких нет: `все выполнены — проверьте ответы`.

Если есть хоть одно включённое направление с target=4 и D7<0.1-EPS, под таблицей появляется пояснение о недостижимости уровня 4 без регулярного внешнего аудита.

Радар отображает только включённые направления. При N<3 вместо радара пояснение, что нужно хотя бы три включённых направления. Масштаб радара 0..4. Целевой контур пунктирный, текущий залитый.
